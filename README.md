# Итоговое задание: Среда для тестирования поведения ОС при нехватке памяти.

## Подготовка среды:

Установить следующие пакеты: sudo apt install -y stress sysstat auditd lm-sensors

## Описание:

## Имитируется процесс с утечкой памяти:

  Создаём файл mem_leak.py, в котором будет имитироваться утечка памяти, с помощью создания датасета и наполнения его данными. Каждые 5 минут происходит добавление новых данных.

## Система автоматически (раз в пять минут) отслеживает состояние:

  Устанавливаем cron, через команду crontab -e открываем файл планировщика и добавляем в него две строки:
  <img width="912" height="649" alt="image" src="https://github.com/user-attachments/assets/a8d68f40-0e65-4281-b317-8062f30ec6cf" />

  С помощью этих строк, каждые 5 минут будут запускаться файлы resource_usage.sh и oom_events.sh, которые будут отслеживать состояние системы. Эти два файла будут созданы позже, пока комментируем две верхние строчки и сохраняем файл планировщика.

## Система отслеживает ресурсы ОС:

  Создаём файл resource_usage.sh, в котором отслеживаем использование памяти, загрузку CPU, использование SWAP и критические события. Использование памяти отслеживаем с помощью команды free -h, загрузку процессоров с помощью mpstat, swap также с помощью free и     критические события ищем в /var/log/syslog по типам событий: emerg|alert|crit|error. Вывод данных происходит в файл resource_usage.log.

## Анализ событий ядра (включая работу OOM-killer):

  Создаём файл oom_events.sh, в котором с помощью команды dmesg отслеживаем работу OOM-killer и выводим другие события ядра, отслеживая файл /var/log/syslog по типам: out of memory|killed|oom. Вывод данных происходит в файл oom_events.log.

## Генерируется диагностический отчёт:

  Создаём файл generate_report.sh, в нём мы прописываем код, который достаёт данные из лог-файлов: resource_usage.log, oom_events.log и выводит их в файл resource_report.txt. В этом файле создаётся отчёт, в котором выводятся в виде таблиц данные об использовании памяти, процессора и swap, которые отслеживались раз в 5 минут. Также выводятся критические события, включая события OOM-killer.
